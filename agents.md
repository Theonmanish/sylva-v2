# AGENTS.md — Sylva Auris 2.0

> Central development instructions for all AI coding agents working on the Sylva Auris website.

---

## 1. Project Identity

**Project:** Sylva Auris 2.0  
**Website:** https://sylvaauris.in  
**Preview:** https://sylvaauris.vercel.app  
**Tagline:** Forest. Reimagined.  
**Business:** Premium terrariums and kokedama  
**Location:** Moodbidri, Karnataka, India  
**Contact:** contact@sylvaauris.in  
**Instagram:** @sylva.auris

Sylva Auris is a premium botanical design brand focused on creating carefully composed miniature landscapes and botanical objects.

The website is being rebuilt from scratch. This is a new implementation, not a modification of the previous website.

The website must communicate craftsmanship, material quality, botanical composition and restrained luxury.

### Core positioning

Sylva Auris aims to position itself as a premium terrarium brand.

The experience should feel closer to a luxury product house, design atelier or premium automotive brand than a conventional plant shop.

The website should communicate quality through its presentation rather than relying on exaggerated claims or decorative effects.

---

## 2. Primary Objective

Build a visually distinctive, responsive and performant website that:

1. Establishes Sylva Auris as a premium botanical design brand.
2. Presents terrariums and kokedama through high-quality visual storytelling.
3. Explains the brand's philosophy and design approach.
4. Showcases product details, materials and craftsmanship.
5. Provides a dedicated gallery for completed work.
6. Offers useful care information.
7. Converts interested visitors into genuine enquiries.

The website is primarily a brand presentation and enquiry-generation platform.

### Not part of the initial scope

Do not independently introduce:

- Ecommerce checkout.
- Online payment processing.
- Customer accounts or authentication.
- Inventory management.
- Order tracking.
- Admin dashboards.
- Complex database infrastructure.
- Subscription systems.
- Unnecessary CMS integrations.

Only introduce these features if explicitly requested.

---

## 3. Brand Design Philosophy

The entire website must follow three principles:

### Restraint

Every visual element must serve a purpose. Avoid unnecessary decorations, excessive animation, visual noise and generic design patterns.

### Material-led presentation

Showcase the actual qualities of the products:

- Glass.
- Moss.
- Plants.
- Roots.
- Gravel.
- Stone.
- Substrate.
- Wood.
- Botanical composition.

Avoid relying on generic nature imagery or vague descriptions.

### Editorial presentation

The website should feel like a carefully art-directed brand experience.

Use deliberate typography, spacing, composition, image placement and transitions.

Do not make the website look like a conventional ecommerce template.

## 4. Visual Identity

### Colour palette

Use the following palette as the foundation of the website.

| Colour | Hex | Usage |
|---|---|---|
| Pitch Black | `#000000` | Primary background |
| Muted Gold | `#B99868` | Accents and subtle highlights |
| Ivory | `#EAE4D8` | Primary text |
| Muted Grey | `#A8A89C` | Secondary text |

Additional shades may be introduced only when required for contrast, borders or image treatment.

### Strict colour rules

- Black must remain the dominant background.
- Gold must be used sparingly.
- Ivory must provide readable text contrast.
- Avoid green-tinted interface elements.
- Avoid excessive charcoal panels.
- Do not introduce unrelated accent colours.
- Do not use bright gradients as decorative backgrounds.

The products themselves should provide the natural colours in the experience.

### Typography

**Primary heading font:** Cormorant Garamond  
**Body and interface font:** DM Sans

Typography should feel elegant, clean and editorial.

Guidelines:

- Use Cormorant Garamond for major headings and selected editorial statements.
- Use DM Sans for paragraphs, navigation, buttons, labels and interface elements.
- Maintain a clear hierarchy.
- Avoid excessive font weights.
- Avoid unnecessary uppercase text.
- Use generous but controlled spacing.

## 5. Design Direction

The intended direction is:

**Dark luxury + botanical editorial + immersive product storytelling.**

The experience should feel sophisticated, cinematic and minimal.

### Required characteristics

- Full black or near-black backgrounds.
- Large, high-quality product imagery.
- Strong typography.
- Deliberate negative space.
- Subtle gold accents.
- Carefully controlled transitions.
- Asymmetric editorial layouts where appropriate.
- Consistent spacing and alignment.
- Smooth and intentional scrolling.

### Avoid

- Generic ecommerce product grids.
- Excessive rounded cards.
- Unnecessary pill-shaped elements.
- Large collections of boxed content.
- Glassmorphism used as decoration.
- Excessive blur.
- Shimmering borders.
- Cursor-following spotlights.
- Artificial glowing beams.
- Unnecessary gradient overlays.
- Excessive parallax.
- Random floating elements.
- Decorative divider lines between every section.
- Template-like layouts.

Do not introduce a visual effect simply because it is technically possible.

## 6. Homepage Experience

The homepage is the most important page.

Its central concept is an immersive transition from a forest environment into a finished terrarium.

### Intended visual progression

1. Begin with an atmospheric forest visual.
2. Gradually reveal details that suggest the presence of a glass enclosure.
3. Transition the visual focus towards the terrarium.
4. Resolve the opening experience into a clear product presentation.
5. Introduce the brand and its design philosophy.
6. Showcase selected creations.
7. Explain the Atelier and customisation approach.
8. Introduce the gallery and care sections.
9. Finish with a clear enquiry-oriented closing section.

This progression should feel seamless rather than like a sequence of unrelated animations.

### Homepage rules

- Do not use a conventional hero with a generic heading and two buttons.
- Do not immediately introduce a large collection-card grid.
- Use one strong hero composition.
- Product imagery must remain visually important.
- Keep text concise.
- Avoid excessive promotional copy.
- Make the enquiry path discoverable.
- Ensure the experience works without animation.

The visual concept must not compromise usability, readability or loading performance.

## 8. Product and Content Accuracy

Never fabricate business information.

The following must be verified before publication:

- Product prices.
- Product dimensions.
- Product availability.
- Plant varieties.
- Materials used in individual products.
- Delivery areas.
- Shipping timelines.
- Customisation options.
- Warranty or replacement policies.
- Visiting arrangements.
- Business operating hours.

If information is unavailable, use a clearly identified placeholder or ask for confirmation.

Do not publish placeholder information as a confirmed business fact.

### Writing style

Use language that is:

- Premium.
- Precise.
- Direct.
- Understated.
- Descriptive.
- Confident.

Avoid:

- Generic AI-generated marketing language.
- Excessive poetic descriptions.
- Empty luxury claims.
- Repeated use of words such as magical, enchanting and breathtaking.
- Unverified sustainability claims.
- Claims that products require zero maintenance.

Describe what makes the actual creation distinctive.

## 9. Photography and Image Guidelines

Photography is a critical part of the brand experience.

Prioritise real Sylva Auris product photographs.

### Image principles

- Use high-resolution images.
- Maintain consistent visual quality.
- Prefer controlled lighting.
- Show the glass and internal composition clearly.
- Pay attention to reflections and backgrounds.
- Use close-ups to communicate material quality.
- Maintain consistent image treatment across the website.

### Asset authenticity

Never present AI-generated imagery as an actual Sylva Auris product photograph.

AI-generated images may be used for:

- Moodboards.
- Concept exploration.
- Background atmosphere.
- Temporary design references.

Actual product galleries and product detail pages should use authentic product photography.

### Image handling

- Use Next.js Image where appropriate.
- Specify image dimensions or aspect ratios.
- Avoid layout shifts.
- Use appropriate image formats.
- Lazy-load images below the fold.
- Prioritise the main hero image.
- Avoid loading unnecessarily large images.

Keep image assets organised and use descriptive filenames.

## 11. Code Quality Standards

All code must be maintainable, readable and appropriately structured.

### TypeScript

- Avoid `any`.
- Define explicit interfaces and types.
- Use reusable types for product and content data.
- Handle nullable values properly.
- Avoid unnecessary type assertions.

### React

- Use functional components.
- Keep components focused.
- Extract reusable components when appropriate.
- Avoid excessively large components.
- Keep state local unless shared state is genuinely necessary.
- Avoid unnecessary `useEffect` usage.
- Avoid unnecessary client-side rendering.

### Components

Separate components according to responsibility.

Examples:

- Navigation.
- Footer.
- Hero.
- Section wrappers.
- Product displays.
- Gallery layouts.
- Enquiry form.
- Animation components.

Do not create abstractions for every small element. Abstractions should improve maintainability.

### Styling

- Prefer reusable design tokens.
- Maintain consistent spacing.
- Avoid scattered arbitrary values.
- Keep responsive behaviour predictable.
- Do not duplicate large blocks of styling.
- Avoid inline styles unless they are necessary for dynamic values.

### General rules

- Do not leave debugging statements in production code.
- Do not commit commented-out experimental implementations.
- Do not ignore TypeScript errors.
- Do not suppress lint errors without justification.
- Do not introduce unused dependencies.
- Do not rewrite unrelated parts of the application.

---

## 12. Animation and Interaction Standards

Motion is an important part of the visual experience, but it must remain controlled.

Use Motion for React for complex transitions where appropriate.

### Animation principles

- Animation should support storytelling.
- Transitions should feel smooth and intentional.
- Avoid excessive movement.
- Avoid distracting looping animations.
- Avoid unnecessary scroll-jacking.
- Avoid delaying content visibility.
- Avoid animations that interfere with navigation.

### Performance

- Prefer transform and opacity animations.
- Avoid expensive layout animations.
- Avoid excessive simultaneous animations.
- Respect reduced-motion preferences.
- Provide a functional experience when JavaScript animation is unavailable.

### Mobile

The mobile experience must not simply reproduce desktop animation at a smaller size.

Adapt or simplify complex effects when necessary.

## 14. Enquiry System

The enquiry system is a key business function.

Visitors should be able to contact Sylva Auris regarding:

- Product enquiries.
- Custom terrariums.
- Kokedama.
- Gifting.
- Bulk or institutional enquiries.
- Other relevant requests.

### Expected behaviour

1. Visitor enters the required information.
2. Client-side validation provides immediate feedback.
3. Data is submitted to a server-side route.
4. Server-side validation checks the submitted data.
5. Spam and abuse protection is applied.
6. The email provider processes the enquiry.
7. A success message appears only after successful submission.

### Technical rules

- Use a Next.js Route Handler.
- Keep email credentials server-side.
- Never expose API keys in client-side code.
- Validate all submitted fields.
- Handle provider errors.
- Prevent duplicate submissions where practical.
- Include appropriate loading and error states.

Do not use a direct `mailto:` link as the primary enquiry system.

The enquiry system must not falsely report success when email delivery fails.

## 17. Security and Environment Variables

Use environment variables for all secrets and external service credentials.

Example:

```env
NEXT_PUBLIC_SITE_URL=http://localhost:3000

# Email provider
EMAIL_API_KEY=
ENQUIRY_TO_EMAIL=contact@sylvaauris.in
ENQUIRY_FROM_EMAIL=

# Optional spam protection
TURNSTILE_SECRET_KEY=
NEXT_PUBLIC_TURNSTILE_SITE_KEY=
```

Rules:

- Never commit `.env.local`.
- Never expose private keys through `NEXT_PUBLIC_`.
- Maintain `.env.example`.
- Validate environment variables.
- Do not hardcode credentials.
- Do not expose server errors or secrets to visitors.

## 19. Development Workflow

All agents must follow this workflow.

### Before implementation

1. Read this `AGENTS.md` file.
2. Read the relevant project documentation in `docs/`.
3. Inspect the existing repository structure.
4. Understand the relevant components and dependencies.
5. Identify the exact task and its scope.
6. Plan the implementation before modifying multiple files.

### During implementation

1. Follow the approved design system.
2. Reuse existing components where appropriate.
3. Keep changes scoped to the task.
4. Avoid unnecessary dependencies.
5. Maintain TypeScript correctness.
6. Check responsive behaviour.
7. Consider accessibility and performance.
8. Do not invent business information.

### After implementation

1. Run TypeScript checks.
2. Run ESLint.
3. Run the production build.
4. Fix errors introduced by the changes.
5. Test the affected functionality.
6. Review the mobile layout.
7. Summarise files changed and important decisions.

Do not claim that a feature works unless it has been tested or its behaviour has been verified.
